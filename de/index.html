Zusammenfassung

Die Systemlandkarte beschreibt die IT-Systeme des Schweizer Agrar- und Ernährungssektors, die Daten, die sie enthalten, die Services, die sie anbieten und nutzen, sowie die Organisationen, die sie betreiben, besitzen oder entwickeln. Sie macht sichtbar, wo welche Daten liegen, woher sie stammen und wer dafür zuständig ist. Sämtliche Inhalte stehen als maschinenlesbare Linked Data zur Verfügung.

1 Einleitung

Im Schweizer Agrar- und Ernährungssektor betreiben Bund, Kantone und private Organisationen eine Vielzahl von IT-Systemen: für Direktzahlungen, für den Tierverkehr, für Kontrollen, für die Nährstoffbilanz oder für die Betriebsführung. Viele dieser Systeme tauschen Daten miteinander aus oder beziehen Daten voneinander. Welche Daten in welchem System liegen, woher sie stammen und wer für ein System zuständig ist, ist jedoch selten an einem Ort zusammenhängend beschrieben. Das erschwert es, Datenflüsse zu verstehen, Mehrfacherhebungen zu vermeiden und die Auswirkungen von Änderungen an einem System abzuschätzen.

Die Systemlandkarte schliesst diese Lücke. Sie beschreibt die Systeme, ihre Daten und ihre Beziehungen in einem gemeinsamen Wissensgraphen.

1.1 Anwendungsgebiet

Die Systemlandkarte richtet sich an Fachpersonen, Architektinnen und Architekten sowie Entwickelnde, die sich einen Überblick über die IT-Landschaft des Agrar- und Ernährungssektors verschaffen oder Datenflüsse zwischen Systemen nachvollziehen wollen. Sie umfasst (Tabelle 1):

  • IT-Systeme und die Services, die sie anbieten und nutzen,
  • die Datensätze, die in den Systemen enthalten sind, und deren Herkunft,
  • die Organisationen, die Systeme betreiben, besitzen oder entwickeln,
  • die Rechtsgrundlagen, auf die sich Systeme und Daten stützen, sowie
  • Subgraphen, die einen thematischen Ausschnitt der Systemlandkarte zusammenfassen.

Nicht Gegenstand sind die Daten selbst: Die Systemlandkarte beschreibt, welche Daten ein System enthält, nicht deren Inhalt. Ebenfalls nicht enthalten sind technische Details wie Server, Netzwerke oder Schnittstellenspezifikationen.

1.2 Aufbau des Dokuments

  • Kapitel 2 erklärt, was die Systemlandkarte abbildet, und zeigt die Begriffe an Beispielen.
  • Kapitel 3 beschreibt, wie diese Begriffe modelliert und miteinander verknüpft sind.
  • Kapitel 4 zeigt, wie die Daten bezogen und gepflegt werden.
  • Kapitel 5 dokumentiert alle Klassen und Eigenschaften.

2 Was die Systemlandkarte abbildet

2.1 IT-Systeme und Services

Ein IT-System ist eine eigenständige Anwendung, die Daten verarbeitet, oft mit einer oder mehreren dazugehörigen Datenbanken, und von einer Organisation betrieben wird, zum Beispiel das Agrarpolitische Informationssystem (AGIS) des BLW. Grössere Systeme können aus Teilsystemen bestehen. Eine eigene Gruppe bilden die Farm-Management-Informationssysteme (FMIS), die landwirtschaftliche Daten erfassen, verarbeiten und bereitstellen, um betriebliche Entscheidungen zu unterstützen, etwa elektronische Feldkalender.

Ein Service ist eine technische Softwarekomponente, die über klar definierte Schnittstellen Funktionen für andere Systeme bereitstellt. So stellt Agate den zentralen Authentifizierungs- und Rollenverwaltungsdienst bereit, über den sich Nutzende bei verschiedenen Systemen anmelden, und der Beitragsberechnungsservice berechnet die Direktzahlungen der Landwirtschaftsbetriebe.

2.2 Datensätze und Datenflüsse

Ein Datensatz ist eine Informationseinheit, die in einem IT-System enthalten ist. Der Begriff ist bewusst weit gefasst: Ein Datensatz kann eine ganze Datenbank sein, eine einzelne Tabelle oder ein Dokument, zum Beispiel die Beitragsdaten in AGIS.

Fliessen Daten von einem System in ein anderes, zeigt die Systemlandkarte nicht nur, dass Daten fliessen, sondern auch welche und woher sie stammen. Wie die Daten übertragen werden, spielt dabei keine Rolle: über eine technische Schnittstelle, per E-Mail-Versand von Tabellen oder durch manuelles Abschreiben.

Einige Datensätze werden gesondert ausgewiesen: Stammdaten wie die BUR-Nummer oder die UID, die von vielen Systemen gemeinsam genutzt werden, sowie Datensätze mit Personendaten oder mit besonders schützenswerten Personendaten.

2.3 Organisationen

Organisationen sind juristische Personen wie Behörden, Unternehmen oder Verbände sowie deren Untereinheiten. Sie betreiben, besitzen oder entwickeln IT-Systeme. Unterschieden werden Organisationen des Bundes, kantonale Organisationen, darunter Landwirtschaftsämter, Veterinärdienste und Beratungsstellen, sowie privatrechtliche Organisationen. Organisationen können hierarchisch gegliedert sein, etwa in Abteilungen.

2.4 Rechtsgrundlagen

Organisationen, IT-Systeme und Datensätze können sich auf eine Rechtsgrundlage stützen, etwa auf einen Artikel des Landwirtschaftsgesetzes (LwG).

2.5 Subgraphen

Ein Subgraph fasst einen thematischen Ausschnitt der Systemlandkarte zusammen, zum Beispiel die Architektur rund um ein bestimmtes System. So lässt sich ein Teilbereich zeigen, ohne die Vielzahl der übrigen Knoten. Tabelle 2 listet die bestehenden Subgraphen.

3 Datenmodell

Dieses Kapitel beschreibt, wie die Begriffe aus Kapitel 2 modelliert sind: welche Angaben erfasst werden, welche davon Pflicht sind und wie die Elemente miteinander verknüpft werden. Die technische Referenz mit allen Eigenschaften ist in Kapitel 5 dokumentiert.

3.1 IT-Systeme

Jedes IT-System hat einen Namen in mindestens einer der Sprachen Deutsch, Französisch, Italienisch oder Englisch, höchstens einen pro Sprache, sowie eine deutsche Beschreibung. Zudem muss jedes System von einer Organisation betrieben werden. Bei 149 der 154 Systeme ist der Betreiber direkt erfasst; die übrigen sind Teilsysteme und werden vom Betreiber ihres übergeordneten Systems betrieben.

Optional sind eine Abkürzung, weitere Namen, eine Webseite, die entwickelnde Organisation, die Rechtsgrundlage und Schlagwörter. Über «ist Teil von» wird ein System einem übergeordneten System zugeordnet, über «nutzt IT-Service» den Services, die es verwendet.

Ein Beispiel: Das Agrarpolitische Informationssystem (AGIS) wird von der Gruppe Agrarinformationssystem AGIS des BLW betrieben, enthält fünf Datensätze und stützt sich auf Art. 165c des Landwirtschaftsgesetzes.

3.2 Datensätze

Jeder Datensatz liegt in einem IT-System, entweder direkt (89 Datensätze) oder als Teil eines übergeordneten Datensatzes (38). So lässt sich eine Datenbank mit ihren Tabellen abbilden.

Datenflüsse werden über die Beziehung «wurde abgeleitet von» erfasst: Der Datensatz im empfangenden System verweist auf den Datensatz, aus dem er stammt. So sind etwa die Kontaktdaten der Milchproduzenten aus den Registerdaten in AGIS abgeleitet. Die Gegenrichtung «informiert» wird automatisch ergänzt.

13 Datensätze sind als Stammdaten gekennzeichnet; andere Datensätze verweisen über «hat Masterdaten» darauf. 26 Datensätze sind als Personendaten gekennzeichnet, 2 als besonders schützenswerte Personendaten.

3.3 IT-Services

Ein Service wird von einem IT-System bereitgestellt und von IT-Systemen oder anderen Services genutzt. Erfasst sind zehn Services; 67 Systeme nutzen mindestens einen davon.

3.4 Organisationen

Jede Organisation hat einen Namen. Von den 270 Organisationen sind 70 Organisationen des Bundes, 51 kantonale Organisationen und 88 privatrechtliche Organisationen. Wo eine Organisation in einem amtlichen Register geführt wird, verweist die Systemlandkarte auf diesen Eintrag, statt die Angaben zu kopieren: Unternehmen werden direkt über ihren Eintrag im Handelsregister (Zefix) identifiziert, Verwaltungseinheiten verweisen über «Registereintrag» auf den Staatskalender.

Die Hierarchie wird über «gehört zu» abgebildet, jeweils nur die direkte Zugehörigkeit. So gehört die Abteilung Direktzahlungen und Beiträge zu Landwirtschaft Aargau. Ausserdem lässt sich festhalten, dass eine Organisation Mitglied einer anderen ist, sie (teilweise) besitzt oder Zugriff auf bestimmte Daten hat, etwa wenn eine andere Organisation als die Betreiberin auf die Daten zugreift.

3.5 Rechtsgrundlagen, Schlagwörter und Subgraphen

Rechtsgrundlagen werden über ihre Adresse in der Systematischen Rechtssammlung des Bundes (Fedlex) identifiziert und tragen ihren offiziellen Titel. Erfasst sind 49 Rechtsgrundlagen, auf die Organisationen, IT-Systeme und Datensätze verweisen.

Schlagwörter ordnen IT-Systeme, Datensätze und Services thematisch ein. Ein Subgraph hat einen Namen und enthält mindestens ein Element.

3.6 Beziehungen

Tabelle 3 zeigt die Beziehungen der Systemlandkarte. Zu den meisten gibt es eine Gegenrichtung, die bei der Verarbeitung automatisch ergänzt wird.

3.7 Qualitätssicherung

Bei jeder Änderung werden die Daten automatisch geprüft, bevor sie publiziert werden. Die Regeln dafür sind in der Shapes Constraint Language (SHACL) formuliert [SHACL]. Sie legen zum Beispiel fest, dass jedes IT-System eine deutsche Beschreibung hat und von einer Organisation betrieben wird, dass jeder Datensatz in einem IT-System liegt und dass jede Beziehung auf ein Objekt der passenden Klasse zeigt. Nur Daten, die alle Regeln erfüllen, werden publiziert.

4 Datenbezug und Nutzung

4.1 Bezug über LINDAS

Die Systemlandkarte ist auf LINDAS, dem Linked Data Service der Bundesverwaltung, publiziert und kann mit SPARQL abgefragt werden [SPARQL]. Das folgende Beispiel listet alle Subgraphen mit der Anzahl ihrer Knoten:

# SUBGRAPHS IN THE SYSTEM MAP
# Returns a table listing all subgraphs, their German name and the number of nodes in said subgraph.

PREFIX schema: <http://schema.org/>
PREFIX dcmitype: <http://purl.org/dc/dcmitype/>
PREFIX systemmap: <https://agriculture.ld.admin.ch/system-map/>

SELECT ?subgraph ?name (COUNT(?node) AS ?nodes)
FROM <https://lindas.admin.ch/foag/system-map>
WHERE {
  ?subgraph a dcmitype:Collection .
  ?subgraph schema:name ?name .
  ?subgraph systemmap:containsNodes ?node .
  FILTER(LANG(?name) = "de")
}
GROUP BY ?subgraph ?name
ORDER BY DESC(?nodes)

Solche Abfragen lassen sich auf https://lindas.admin.ch/sparql/ ausprobieren. Weitere Beispiele liegen im Repository unter src/sparql/queries/.

4.2 Visualisierung

Ein separates Frontend zeigt die Systemlandkarte als interaktiven Graphen im Browser an und kann auf einzelne Subgraphen gefiltert werden.

4.3 Einschränkungen

Fehlt in der Systemlandkarte eine Angabe, heisst das nicht, dass es sie nicht gibt, sondern nur, dass sie nicht erfasst ist. Ist ein Datensatz nicht als Personendaten gekennzeichnet, kann er dennoch Personendaten enthalten.

4.4 Pflege

Die Systemlandkarte wird auf GitHub gepflegt. Fehler oder fehlende Einträge können als Issue gemeldet werden. Die Inhalte stehen unter der Lizenz CC BY 4.0 und dürfen unter Nennung der Quelle frei verwendet werden.
